# Resident device search implementation

**Status:** Informational

Implementation plan, selected against accepted SPEC-0007,
SPEC-0008, SPEC-0009, SPEC-0010, SPEC-0011, SPEC-0012, SPEC-0013, SPEC-0014 and
SPEC-0015. This does not replace those contracts or claim engine qualification.

The explicit owner goal authorizes completion without a new human approval ritual.
Production is JS plus restricted Device-JS through public CUDA-JS alpha22 and
CUDA-JS-Tensor alpha10. No native escape or host active-search relaunch is allowed.

Files: canonical compiler child `resident-device-search-contract.mjs` declares
typed owner hook signatures; `resident-device-search.mjs` will normalize selected
owners, emit their contributions, and derive finite storage extents.
`device-continuation.mjs` normalizes the closed operation topology, canonical
`program-package` preserves execution profiles/reachable closures, and
`integration.cuda-js` mechanically realizes those operations and external ports.
The Tensor evaluator adapter retains request slot/request generation/batch
incarnation, cancellation, result readiness and publication while extending
the selected execution protocol to one uniform block32 item.

Admission owns production of complete legal candidate spans, separate from lazy
child materialization. Output only copies already-ready actions and facts into
immutable borrowed slots. It does not generate actions or change search.
Policy consumes protected complete views with an explicit readiness mask and
owns numeric/proof meaning. Evaluator owns encoded request/result staging and
all request/batch/scatter dispositions; Policy alone cannot invoke Tensor as
a substitute lifecycle. Session command identity and generation are each four
u32 words; the u32 mailbox notification is only a hint. Ready-successor advance,
general admission, and optional structural reroot remain distinct.

The first memory selection is lazy second-chance: one clock candidate per
allocation attempt, protect focus/path/evaluation/work/borrow incarnations,
generation advance before reuse, lazy rejection of stale incoming references,
contiguous candidate spans with bounded coalescing allocation metadata.
Graph-wide mark/sweep is not selected. Pressure yields no visits/value/proof and
does not reset the resident graph. Typed pressure keeps legal output and explicit
focus admission responsive. Counters describe live objects, not high-water slots.

Qualification order: cold identity/topology/ABI falsifiers; independent non-domain
device graph/proof/pressure/incarnation tests; selected evaluator collective tests;
actual continuation with focus changes during pending work and read-only output;
then the exact product composition and full-game pressure/reclamation tests.
Native probes are serialized with the product author and must prove clean teardown.

## Cold storage and clocked input

Actual UCI phase evidence found roughly 1.4 seconds of input-loop blocking when
the first position allocated/copied every cold resource and ignition scanned
large zero views synchronously before the queued `go` line was received. The
absolute clock origin was already correct; moving that origin cannot fix the
lost input time.

Package `0.0.0-dev.2` adds public storage preinitialization before consumer
readiness. It checks owned snapshots and writes device storage without executing
root admission or search. Exact duplicate proofs are checked once; large checks
yield in bounded chunks. Later ignition accepts only exact declared cold input
views, then performs existing GPU bootstrap/readiness and one continuation.
Full-resource replacement, protected zero/content ranges and internal aliases
are rejected. The resident Device-JS source and owner callback ABI are unchanged.

A generic Node26.11/CUDA-JS22 physical probe rejected invalid last-byte zero
content and storage substitution, observed 286 heartbeat ticks during 294 ms
validation, completed bulk writes before any initializer, then staged a four-byte
input and ignited once. Cancellation and graceful teardown reported zero live
and orphan resources. This is mechanism qualification; actual product clock
responsiveness must be observed separately. Both prior package bytes and prior
reference chains remain historical records, with a separate dev.2 chain.

## Terminal authority and exhaustion

Package `0.0.0-dev.3` latches the first authoritative stop before request/path
drain. Subsequent disposal or consumption failures retain their own bounded
drain disposition. The public terminal protocol declares that separate field
after the complete legal-row region; successful quiescence requires it to be
zero alongside the existing residue and lease-balance facts. It does not alias
the observer header or first-stop field.

Session rejects exhausted focus/publication generations before Domain replay,
target admission or snapshot reservation. A failed reserved publication releases
its writing slot. Typed command acknowledgements remain available on rejection.
Isolated native fault injection qualifies cancellation plus disposal failure,
prior failure plus drain failure, and clean cancellation. A separate generated
Session probe qualifies both exhaustion boundaries with no admission/reservation.
These are bounded owner falsifiers, not composed chess or strength evidence.

An immutable Output tail also carries two explicitly scoped cumulative node
facts: a selected Evaluator-ready result accepted by the selected Policy, and a
later ordinary traversal directed by that same Policy after acceptance. New
node incarnations start with neither fact. Rejection and traversal without
acceptance cannot create them. They do not assert universal or current model
cache validity; product interpretation requires the exact selected identities.
Capture occurs only at controller quiescent boundaries, and observers consume
the captured copy. Separate tail fields copy the root incarnation's cumulative
Evaluator admission and ready-observation counts. A flag already present before
returning to a root proves historical disposition only; it cannot alone prove
fresh reuse after that return. Those counters permit a product to test subsequent
work without a new root request under its exact selected cache semantics.
Earlier packages and receipts retain their historical scope.
